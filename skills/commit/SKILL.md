Analyze my code changes using a single `git diff -U10` and determine the optimal commit strategy following Conventional Commits (`type(scope): description`).

If all changes are related to a single feature/purpose:
- Create one commit with a comprehensive message

If changes serve different purposes:
- Split into multiple logical commits by feature

Other sessions may share this checkout: commit this session's files by path, `git add <paths> && git commit -m … -- <paths>` in one batch, which leaves what others staged alone; a file both edited goes in whole. Name the changes you left.
Commit onto a live branch: when `gh pr view --json state -q .state` prints `MERGED`, move your changes to a new branch from `origin/main` first.
Always run git commands from the current working directory without changing to the repository root - git works from any subdirectory.
Never use `git add -f` to force-add gitignored files.
Never include AI attribution in commit messages (no "generated by Claude", no `Co-Authored-By` trailers).

Remove agent-created RFCs and decision documents unless explicitly requested by the user; carry important decisions and context in commit messages.
